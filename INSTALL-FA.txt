VapePad Market — بسته رابط کاربری تنوع محصولات

این بسته شامل تغییرات رابط کاربری و SQL برای تنوع محصولات است.

مهم: این بسته هنوز برای انتشار نهایی آماده نیست. تابع Edge Function با نام create-order باید جداگانه به‌روزرسانی شود تا variant_id را اعتبارسنجی کند، موجودی همان تنوع را به‌صورت اتمیک کم کند و اطلاعات تنوع را در vm_orders.items ذخیره کند. کد فعلی create-order که قبلاً بررسی کردیم این کارها را انجام نمی‌دهد. تا قبل از تکمیل آن تابع، این فایل‌ها را روی سایت اصلی منتشر نکنید و سفارش واقعی آزمایشی ثبت نکنید.

محتوای تغییرات:
- جدول vm_product_variants برای طعم، رنگ و مدل با موجودی مستقل
- نمایش فقط وضعیت موجود/ناموجود برای مشتری؛ عدد موجودی در کارت محصول نمایش داده نمی‌شود
- انتخاب تنوع قبل از افزودن به سبد خرید
- نمایش انتخاب تنوع در سبد خرید و ارسال variant_id در payload سفارش
- افزودن، ویرایش و حذف تنوع و تغییر موجودی از پنل مدیر
- دسته‌بندی قلیان
- حفظ قیمت و تخفیف و سایر امکانات قبلی

مراحل بعدی:
1. ابتدا از نسخه فعلی سایت و دیتابیس نسخه پشتیبان داشته باشید.
2. SQL موجود در supabase-migration.sql را در SQL Editor اجرا کنید. اگر جدول vm_product_variants را قبلاً ساخته‌اید، دستورات IF NOT EXISTS با آن سازگارند.
3. قبل از جایگزینی فایل‌های سایت، تابع create-order باید با جدول تنوع‌ها و کاهش اتمیک موجودی هماهنگ شود.
4. پس از آماده‌شدن تابع، فایل‌های index.html، style.css و app.js را در ریشه مخزن GitHub جایگزین کنید.

نوع تنوع در پنل مدیر:
- flavor = طعم
- color = رنگ
- model = مدل

قیمت و موجودی را سرور باید از دیتابیس بخواند؛ هیچ مبلغ یا موجودی ارسالی از مرورگر قابل اعتماد نیست.
